## 1. このツールは何をするか

社内の各部署がクリエイティブ室へ制作依頼を出すためのWebフォーム。
送信すると Notion のデータベースにページが1つ作られ、依頼者がそのページのURLを Slack でクリエイティブ室に共有する。

- フォーム: `https://crplayground.github.io/toolbox/creative-process/`
- Worker: `https://creative-process.yukimiyakawa.workers.dev`
- 保存先: Notion データベース「クリエイティブプロジェクト」（`37f6d45e-597d-8046-b35e-e0a310821fd3`）

**Notionページが唯一の正本。** 依頼内容の確認・修正はNotionページ上で直接行う。フォーム側に編集機能は持たせない。

## 2. 画面フロー

```
[フォーム]
 STEP1 依頼者      … Googleログイン（@crazy.co.jp のみ）＋ 所属部署
 STEP2 依頼種別    … 新規／改訂／転用／相談 の4択
   ↓ 選ぶとSTEP3が現れ、STEP3の先頭までスクロールする
 STEP3 依頼内容    … 選んだ種別に応じた設問だけを表示
   ↓ 送信
[完了画面]           … NotionページのURLをコピー → Slackへ手動で共有
```

- **送信ボタンは、必須項目がすべて埋まるまで押せない。**
- 依頼種別を切り替えると、表示中の設問が入れ替わる。**入力済みの値は消さない**（戻したときに復元される）。
- 送信できないときは、送信ボタンの直下にエラーメッセージを出す（§6）。

## 4. スケジュール欄の仕様

```
[スケジュール] [納期目安表をみる]
希望納品日や原稿素材の格納日などスケジュール感を教えてください。
┌ 日付 ┬ 内容 ┬ × ┐   ← 行を増やせる
└ ＋ 日程を追加する ─┘
```

- 1行＝**日付 ＋ 内容テキスト**。内容のプレースホルダは「デザインチェック・上長提案・校了など」。
- 「＋ 日程を追加する」で行を増やす。各行の右端の×でその行を消す。**1行目は消せない**（消すと空にできてしまうため、内容を空にする形にする）。
- **日付は未入力のあいだ今日の日付をプレースホルダとして表示し、実値は空**にしておく。誤って今日が希望納品日として登録されるのを防ぐため。
- 上限は20行。
- 日付だけ・内容だけの行も送信を許す（片方だけ埋まっている状態にも意味があるため）。両方空の行は送信時に捨てる。

## 5. 画像添付の仕様

- 複数枚を選べる。`accept="image/*"`。
- 選んだ画像はサムネイル一覧で確認でき、1枚ずつ取り消せる。
- 送信時にWorkerへ渡し、**Notion File Upload API でページ本文に埋め込む**。
- **アップロードは送信の応答後にバックグラウンドで行う**（2026-08-11変更・全枚数を並列アップロード）。
  応答は画像の処理を待たずに返るため、添付枚数が増えても送信の待ち時間は変わらない。
  - 副作用：完了画面から**すぐ**Notionページを開くと、参考画像が数秒〜十数秒遅れて現れる（許容済みの仕様）。
- **アップロードに失敗しても送信自体は成功させる。** 失敗した枚数はページ本文に「⚠️失敗N枚」として記録する
  （本文への追記が丸ごと失敗した場合も、同様に⚠️の段落を本文に残す）。

### 8-6. Driveの案件フォルダ自動作成

送信のたびに案件フォルダを作り、その中に `01_支給素材` / `02_作業データ` / `03_納品データ` を用意する。
作ったフォルダのURLは、プロパティ「データ格納先」に書き戻す。

**フォルダ階層（2026-08-11変更）**

各事業フォルダの直下には**制作物の種別ごとのフォルダ（棚）**があり、案件フォルダはその中に作られる。

```
02_案件管理/
├── <対象事業・部署>/                 … 18事業
│   ├── 01_イベント・キャンペーン/
│   ├── 02_スライド・ePDF/
│   ├── …（§7-3の順に10棚）
│   └── 10_その他（基本的に使用しない）/
│       └── no00001_案件名/           … 案件フォルダ（自動作成）
│           ├── 01_支給素材
│           ├── 02_作業データ
│           └── 03_納品データ
└── 相談/                             … 棚を持たずフラット
```

- 棚は**名前で解決する**（事業フォルダ直下から「数字_種別名…」に一致する子を探す）。無ければ正式名で自動作成する。
  Drive側で棚の番号や補足文言が変わっても、種別名が先頭に残っていれば追従できる。
- 番号のないフォルダ＝ツール導入前の過去データ。過去データは遡って採番せず、該当する棚へ手で振り分けるだけでよい。

**起票番号**

- `no` ＋ 5桁ゼロ埋めの通し番号（例 `no00001`）。**対象事業・部署ごとに独立した連番**で、
  IWAI-婚礼の `no00001` と CGM-婚礼の `no00001` は別物。
- 発番元はNotion。DBを「対象事業・部署＝その事業」で絞り、「起票番号」の最大値に +1 する。
  カウンタをどこにも持たないので、Notionと番号が食い違うことがない。
- 常に5桁なので、文字列のまま並べても数値順になる。
- Notionページを削除すると、その番号は欠番になる（最大値方式のため）。運用上の実害はない。
- **全社で一意なキーが要るときは「依頼ID」（Notionの自動採番）を使う。** 起票番号は事業ごとの通し番号なので、
  単独では一意にならない。
- **改訂は「対象事業・部署」をフォームで聞かない。** 親フォルダから事業フォルダをさかのぼって特定し、
  採番のうえNotionの「起票番号」「対象事業・部署」に書き戻す。相談フォルダ配下の案件は
  フォルダ名の `[略称]_` から事業を引く。**親が `02_案件管理` の外にある送信は受け付けない**
  （Workerの事前チェックが400で弾き、Notionページを作らない。→依頼種別「転用」を案内）。

**置き場所と名前**

| 依頼種別 | 置き場所 | フォルダ名 |
|---|---|---|
| 新規 | `02_案件管理/<事業>/<種別の棚>/` | `no00001_案件名` |
| 転用 | `02_案件管理/<事業>/<種別の棚>/`（**元と並列**） | `no00002_案件名` |
| 改訂 | 「親フォルダのURL」が指すフォルダの**中**（`02_案件管理` 内に限る） | `no00033_案件名` |
| 相談 | `02_案件管理/相談/`（フラット） | `[略称]_no00005_案件名` |

- **改訂**は貼られたURLのフォルダをそのまま親にする。**親は `02_案件管理` の事業フォルダ（または相談）配下に限る**＝
  範囲外・アクセス不可は送信時に400で弾く（2026-08-11決定。散在する過去データの改訂は「転用」で受ける）。
  ファイルのURLが貼られたらその入れ物から始める。貼られたのが「番号付き案件フォルダの中の番号付きフォルダ」
  なら1段引き上げる（＝**入れ子は2階層で止める**）。
- **転用**は「転用元のデータ」を置き場所に使わない。選ばれた種別の棚に、新規と同じ要領で**元と並列**に作る。
- **相談**は事業フォルダに散らさず `相談` に集める。どの事業か分かるよう、略称（`｜` より前）を先頭に付ける。
  番号は事業ごとの連番をそのまま使うので、案件化したらフォルダを事業フォルダの該当する棚へ移すだけでよい
  （リネーム不要・番号の衝突なし。移動は手作業）。
- 種別が未選択・未知のとき（旧フォームからの送信等）は、棚を使わず事業フォルダ直下に作る。
- 案件名は60字で切り詰め、`/` `\` はハイフンに、制御文字は除去する。空なら「無題」。

**事業フォルダはIDで指定する**

フォルダ名で探すのではなく、18件のフォルダIDをコードに持って直接指定する。
フォルダ名を変えても壊れず、名前のわずかな表記ゆれで作成に失敗することもないため。

**失敗したときの動き**

Drive処理は任意扱いで、失敗しても依頼の登録は成立させる（依頼者に再送信させない）。

| 状況 | 動き |
|---|---|
| サービスアカウント未設定 | フォルダを作らずスキップ。Notionページは通常どおり作られる |
| 起票番号が採れなかった | 番号もフォルダも付けずにページだけ作る |
| 事業フォルダのIDが見つからない | スキップ（Notionページはそのまま） |
| Drive APIがエラー | スキップ。同上 |
| サブフォルダの作成だけ失敗 | 親フォルダはそのまま使う |
| 「データ格納先」への書き戻し失敗 | フォルダは残る。URLは手で貼る |
| 改訂でフォルダを作れなかった | ページ本文に⚠️の注記を残す（手動作成を促す） |

**処理の順番（2026-08-11変更＝応答の高速化）**

```
【応答前＝同期】
① 改訂のみ：親フォルダの事前チェック（02_案件管理の外・アクセス不可は400で弾く）
② 起票番号を採番（Notionを検索して最大値+1。改訂を除く）
③ Notionページ作成（起票番号を含む・画像なし）→ ここで送信者に応答を返す
【応答後＝バックグラウンド（互いに並走）】
④ 参考画像を並列アップロードし、ページ本文の末尾に追記する
⑤ Driveに案件フォルダ＋3点セットを作成（改訂の採番もここ）
⑥ フォルダURLをNotionの「データ格納先」に書き戻す
```

- フォームが応答から使うのは NotionページのURL のみ。④〜⑥の結果は応答に含まれない。
- 応答が速く返るぶん、完了画面の表示は数秒早い。直後にNotionページを開くと
  参考画像と「データ格納先」が数秒〜十数秒遅れて現れる（許容済みの仕様）。

## 9. 完了画面

送信に成功したら、フォームを隠して完了画面に切り替える。

切り替えの前に**送信アニメーション**（§9-1）が流れる。

絵文字は**Noto Animated Emoji**（Google Fonts CDN＝`fonts.gstatic.com/s/e/notoemoji/latest/<code>/512.webp`）。
Figmaのemojiセクションと同じ16種から**送信のたびにランダムで1種**を選び、完了画面（64px）と送信アニメーション（104px）に同じものを表示する。
抽選と読み込みは**送信ボタンを押した時点**に行うため、表示時にはロード済み。WebP→GIF→Unicode絵文字の順にフォールバックし、
`prefers-reduced-motion` ではアニメーションを読み込まずUnicode絵文字を出す。
16種＝😆😎🤩😍💡🪩💎🌟👏🎉🛎️🪙🎯🪇🔮🚩

```
😆(GIF)
＼ プランニングシートを作成しました! ／
あと1ステップで、依頼を起票できます!

NotionページのURLをコピーして [Slackチャンネル] に貼り付け。
 ・ ANV含む婚礼全般に関する制作依頼・相談は、@笹原光 / Hikari Sasahara 宛に投稿してください。
 ・ それ以外（食・CBX・採用）の制作依頼・相談は、@宮川雄気 / Miyakawa Yuki 宛に投稿してください。
依頼内容の確認・修正はNotionから行えます。

[🔗 NotionのURLをコピー]   ← 全幅・青枠（btn/tertiary-blue/leftcon・icon/link）
[Ⓝ Notionで編集]           ← 全幅・グレー枠（btn/tertiary/leftcon・logo/Notion）

※初めて依頼した方は、ページを開くとアクセス権リクエストが表示されます。そのまま承認依頼を出してください。

別の依頼を起票する
```

- 「Slackチャンネル」は `https://crazyincworkspace.slack.com/` へのリンク（新しいタブで開く）。**特定のチャンネル名を出さない**のは、制作依頼を受け付けるチャンネルが複数あるため。
- 「NotionのURLをコピー」を押すと2.2秒間だけ青ベタ＋「コピーしました」表示に変わる。
- 「別の依頼を起票する」でフォームを初期状態に戻す。

### 9-1. 送信アニメーション

送信成功のレスポンスを受け取ったら、完了画面へ切り替える前に全画面のアニメーションを流す（Figma `submit-animation` 86:2083）。

1. サンビームのグラデーションが画面を**下から覆う**（0.45秒・clip-path）
2. 覆い切ったタイミングで背面をフォーム→完了画面に差し替える
3. 絵文字（Noto Animated Emoji・104px表示）がバウンスしながらポップイン、白文字のタイトル・サブタイトルが下からスライドイン
4. 約2.2秒後にフェードアウトし、完了画面が現れる

`prefers-reduced-motion: reduce` の環境ではアニメーションを流さず、即座に完了画面へ切り替える。

> **この共有ブロックは暫定機能。** Slack Bot による自動投稿を導入するまでの繋ぎとして、依頼者に手動で共有してもらっている。
> 導入時にブロックごと削除できるよう、HTML・CSS・JS のいずれもコメントで囲っておく。

## 11. Googleログイン

**One Tapによる自動ログインを主、自作ボタンをフォールバック**とする2段構え。
ログインボタンは自前のHTML/CSSで作っているため、Googleが描画する公式ボタンは使わない。

### 11-1. ① One Tap（自動・主経路）

ページを開いた時点で `google.accounts.id` を `auto_select: true` で起動する。
ブラウザでGoogleにサインイン済みの人は、**ボタンを押さずにログイン状態になる**。

```
[フォーム] ページ読み込み
   → google.accounts.id.initialize({ auto_select: true, use_fedcm_for_prompt: true }) → prompt()
   → コールバックでIDトークン（JWT）を直接受け取る
   → 画面側で hd と メールアドレスの末尾を先読みチェック（@crazy.co.jp 以外はここで断る）
   → 氏名とメールアドレスを表示し、送信時にIDトークンを添える
[Worker] POST /submit でそのIDトークンを署名検証してから登録する
```

- `use_fedcm_for_prompt: true` を必ず指定する（Chromeの新方式。指定しないと将来One Tapが出なくなる）。
- **One Tapが出せない環境では黙って出ないだけ**で、エラーにはしない。自作ボタンがそのまま使える。
  （サードパーティCookieが無効／Googleに未サインイン／過去に閉じた直後のクールダウン中／FedCM非対応ブラウザ など）
- 画面に出す氏名・メールは**トークンから取り出した表示用の値**。信用の起点ではない。
  Notionに書くのは、あくまで**Workerが署名検証して取り出した値**。

### 11-2. ② 自作ボタン（手動・フォールバック）

One Tapが出なかったとき、別のアカウントに切り替えたいとき、キャンセルしたときの手段。
**認可コードフロー**を使う。

```
[フォーム] Googleでログインする を押す
   → google.accounts.oauth2.initCodeClient（ポップアップ）で認可コードを受け取る
[Worker] POST /auth/exchange に認可コードを送る
   → Google のトークンエンドポイントでIDトークンに交換（クライアントシークレットを使う）
   → IDトークンの署名とクレーム（発行元・aud・exp・hd・メール確認済み）を検証
   → { idToken, name, email, exp } を返す
[フォーム] 氏名とメールアドレスを表示し、送信時にIDトークンを添える
[Worker] POST /submit で同じIDトークンをもう一度署名検証してから登録する
```

- **認可コードフローは自動起動しない。** ポップアップを開くため、ブラウザのブロッカーに止められる。必ずボタンの操作を起点にする。
- 「別のアカウント」を押したら `google.accounts.id.disableAutoSelect()` を呼ぶ。
  これをしないと、One Tapの自動ログインが同じ人で入り直してしまう。

### 11-3. 共通

- **どちらの経路でも、最終的な判定はWorker側のIDトークン署名検証**（発行元・aud・exp・`hd`・メール確認済み）。
- **クライアントシークレットは Worker Secrets（`GOOGLE_CLIENT_SECRET`）にのみ置く。** フォームHTMLにもリポジトリにも書かない。
- ポップアップ方式のため、トークン交換の `redirect_uri` は `postmessage` を使う。
- `/auth/exchange` も `/submit` と同じく `ALLOWED_ORIGIN` のオリジンからしか受け付けない。
- ログインの有効期限は約1時間。切れたら送信時に検知して、再ログインを促す。

### 11-4. GCP側の設定

- **本番（`https://crplayground.github.io`）は追加設定不要**。One Tapも認可コードフローも、
  すでに「承認済みの JavaScript 生成元」に入っているオリジンで動く。
- **ローカル（`http://localhost:8000`）でOne Tapを試したい場合だけ**、同じ欄に `http://localhost:8000` を追加する必要がある。
  ローカル確認が済んだら消してよい。追加しない場合、ローカルではOne Tapが出ず、自作ボタンの経路だけが確認できる。
